# LuaTools macOS acceptance ledger

The current Windows implementation uses LuaLoader (`winmm.dll`, LTSP), with the desktop `CefInjectorService` and a Millennium-compatible JavaScript polyfill. The macOS target must follow LuaLoader as the primary loader, not require Millennium. The desktop CDP bridge now owns LuaTools RPC even when Millennium is present. Its `window.Millennium` compatibility wrapper passes unrelated plugins through unchanged. Native LuaLoader bootstrap/activation remains to be implemented and tested in Steam.

This checkout is not yet the requested full release. Its native SwiftUI surface remains incomplete. Track full requirements together with `BetterSteamTools/macos/IMPLEMENTATION_STATUS.md`.

Verified: atomic Lua replacement (including same source/destination), explicit remove errors, strict HTTP framing and methods, malformed AppID rejection, bounded fragmented TCP requests, a real loopback listener, origin rejection, and explicit errors for unknown/unimplemented RPC routes. `LuaToolsMacSelfTest` runs those cases without changing a real Steam installation.

The CDP transport now keeps a single correlated response reader per socket and waits for actual evaluation results. `LuaToolsCDPSelfTest` runs against a real loopback WebSocket fixture (fragmented/out-of-order replies, notifications, cancellation, timeout, disconnect, validated discovery targets, default-context and nonce isolation, navigation, LuaLoader selection, rejection of a legacy-loader handshake, failed frontend acknowledgement and reconnect). `Tests/CDP/bridge.test.cjs` executes the bridge in separate JavaScript realms and verifies response IDs, stale replies, error propagation, pending promise disposal, LuaLoader priority, preservation of other Millennium plugins, exact restoration of the original API on disposal and pending requests surviving late Millennium activation. The bridge does not set the frontend's UI-ready flag. These tests establish transport behavior, not Chromium/Steam end-to-end acceptance.

The default inspector authorizer now uses libproc to enumerate TCP listener owners and their executable paths before discovery and again before opening returned WebSocket targets. It accepts only loopback listeners owned by native helper executables inside the selected Steam bundles. Tests inspect a real loopback test listener and reject foreign/Wine owners, wildcard listeners, another installation and a helper symlink escaping the approved app. A read-only diagnostic against the host's occupied port 8080 identified Windows Steam/CrossOver owners and refused native authorization. This prevents confusing the running Windows client with the native macOS acceptance target; it does not prove native Steam activation. WebSocket fixtures explicitly inject a test authorizer instead of weakening the production default.

Both the native CDP composer and Millennium Lua backend embed the plugin's base CSS, theme metadata and theme styles in the delivered frontend; relative theme URLs no longer need to resolve on the Steam store origin. The self-tests compose the real packaged assets, reject directory traversal in theme names and verify the mocked Lua composer. Settings/database/fixes methods now forward real backend results instead of returning empty successful placeholders.

Lua package installation reads ZIP local and central records in bounded memory instead of extracting archive paths to disk. It rejects traversal, symlinks, overlapping records, duplicate paths, encrypted entries and CRC errors, and enforces expanded-size limits. Raw and ZIP-wrapped Steam manifests are parsed for depot ID, GID, encrypted filenames and installed size; their declared identity must match the destination filename, while original bytes are preserved. `LuaToolsMacSelfTest` exercises actual stored/deflated ZIPs, ZIP64 end/entry records, wrappers, metadata mismatch, path traversal, symlinks, CRC corruption and preservation of an existing Lua after failed installation. Multi-volume archives are rejected; durable multi-file rollback across process crashes remains required. The SwiftUI shell has macOS navigation for Resumen, Juegos, Lua y depots, Operaciones and Ajustes, with file pickers for `.lua` and ZIP packages.

The UI no longer edits Steam Info.plist through a second unsafe implementation: activation delegates to the packaged BetterSteamTools CLI and requires a signed manifest. The packaged helper and approved hook payload still need release packaging.

Still required: complete desktop UI and service parity; downloads and source selection; builds/fixes/manifests and settings; verified dependency/install/update/rollback lifecycle; plugin artifact authentication; native LuaLoader bootstrap/activation and live CDP/frontend behavior; process/menu-bar/LaunchAgent integration; signed app/DMG generation; and all live Steam/game acceptance tests. Pure Lua tests cover separate Steam data/client paths, safe POSIX quoting, backend service identity, invalid AppIDs, capabilities, asset composition and forwarding every frontend RPC name. These use mocked Millennium modules; the plugin assets have not been proven to work against a live macOS Millennium runtime.
