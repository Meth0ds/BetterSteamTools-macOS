# Authenticated Steam build approvals

A build approval is a JSON envelope with `keyID`, base64 `payload`, and base64 Ed25519 `signature`. The signature covers the exact decoded payload bytes. `SteamBuildManifest.verify` checks an explicit trusted public key, schema version, architecture and hashes before accepting it.

The payload includes `schema: 1`, a Steam `build`, `architecture: arm64`, SHA-256 `files` entries for `steam_osx`, `steamclient.dylib` and `steamui.dylib`, and the approved BetterSteamTools `payloadSHA256`. Client hashes refer to the inner client directory under `Steam.AppBundle/Steam/Contents/MacOS`, not the outer bootstrapper.

The release trust store is intentionally empty while no actual macOS Steam build and matching complete hook implementation have passed acceptance. No release approvals or private signing keys are generated by ordinary builds or tests. Self-tests generate ephemeral keys only for tamper and unknown-key tests.

Before release, pin maintainer public keys in source, produce the exact-build hook signatures, sign the approval payload and run live integration acceptance. Hashes alone are not signatures.

The installer persists the envelope at `Steam.app/Contents/Resources/BetterSteamTools.build.json`, where codesign seals it as a resource. The injected C++ runtime calls the same Swift/CryptoKit verifier through `BSTVerifyBuildManifest`; it accepts no runtime environment variable as a trust root. CMake accepts `BST_MANIFEST_KEY_ID` and `BST_MANIFEST_PUBLIC_KEY_HEX` for an explicitly trusted build; their empty defaults disable activation. The installer trust store must contain the same approved public key before release.
